🏗️ System Architecture

Overview

KOEL is a low-latency, multilingual voice-bot platform for Indian financial services achieving sub-300ms conversational turn latency.

Frontend (React SPA) ↓ REST + WebSocket VoiceBot Orchestrator (8100) ├→ STT Service (Sarvam → Groq → Stub) ├→ NLP Service (Groq → Stub) ├→ TTS Service (Sarvam/Magpie/Groq → Stub) └→ CRM Service (Synthetic) ↓ ┌─────┬──────┬──────┐ ↓ ↓ ↓ ↓ Redis Postgres Groq NVIDIA NVCF

Key Principles

  • Stateless — All call state in Redis with TTL
  • Provider Isolation — STT/NLP/TTS swappable
  • Sub-300ms Latency — Streaming + filler injection
  • Graceful Degradation — Failures cascade, never crash
  • Exactly-Once Finalization — Every call persisted

🔌 REST API Reference

Base URL: http://localhost:8100 (dev). All endpoints require JWT bearer token.

Authentication

POST /v1/auth/login — Get access token (demo/koel-demo)

POST /v1/auth/ws-token — Get short-lived WebSocket token (120s)

Bot Management

GET /v1/bots — List all bots

POST /v1/bots — Create new bot (201)

GET /v1/bots/{bot_id} — Get single bot

Sessions & History

POST /v1/sessions — Start call (returns session_id + ws_token)

GET /v1/calls — List calls (filters: bot_id, outcome, language)

GET /v1/calls/{call_id} — Get call + transcript

Error Codes

  • 409 Conflict — Customer on DND list
  • 403 Forbidden — Outside calling hours
  • 404 Not Found — Bot inactive/missing

🔌 WebSocket Protocol

Client → Server Messages

  • audio_chunk — Streamed mic audio (audio_b64, is_final, sample_rate)
  • barge_in_candidate — VAD fired while bot speaks (partial_text, speech_duration_ms)
  • pong — Heartbeat reply (does NOT reset no-input timer)
  • end_call — User hangup

Server → Client Messages

  • call_state — Session status (connecting, bot_speaking, listening, processing, escalating, reconnecting, ended)
  • transcript — Bot/customer utterance (speaker, text, tone, intent, language)
  • audio_chunk — Synthesized speech (audio_b64, duration_ms)
  • filler — Injected when NLP is slow (masks latency)
  • tts_kill — Interrupt signal (barge-in detected)
  • reconnected — Session resumed confirmation
  • call_ended — Final summary (outcome, escalated, turns, trace_id)

⚙️ Core Components

1. VoiceBot Orchestrator (8100)

Central hub for session management, pipeline orchestration, and resilience logic.

2. Speech-to-Text (8101)

✅ Real Sarvam Saaras — Trained on Indian code-mixed speech. Auto-detects language, returns genuine confidence for escalation gating. Falls back to Groq Whisper (language-pinned) then Stub.

3. NLP Service (8102)

✅ Real Groq llama-3.3-70b-versatile — Intent classification, response generation, tone assignment. RAG-augmented with pgvector. Falls back to keyword heuristics on error.

4. Text-to-Speech (8103)

Multi-provider routing by language:

  • Hindi: Sarvam Bulbul (romanized-native) → NVIDIA Magpie (Devanagari-native, NVCF gRPC) → Groq Orpheus → Stub
  • Hinglish: Sarvam Bulbul (verified 1.0 confidence with STT) → Groq Orpheus → Stub
  • English: Groq Orpheus → Stub

5. CRM Service (8104)

Synthetic customer database. Contract: GET /customers/{id}, POST /flags, POST /interactions. Swappable for real CRM.

📚 Key Algorithms

1. Dual-Gate Barge-In

Gate 1: Client VAD fires. Gate 2: Duration + dictionary classification. If <300ms or backchannel → ignore. Else → TTS_KILL.

2. Filler Racing

Race NLP against 300ms timeout. On timeout, inject filler clip while awaiting response.

3. Pong-Independent No-Input

Heartbeat pongs don't reset no-input timer. Only real audio frames do. Re-prompt extends window.

4. Dropped-Call Finalizer

On disconnect: status=reconnecting, TTL=15s. Detached task finalizes after grace window.

5. Language Fallback

STT returns language + confidence. If unsupported & above threshold → apologise + escalate.
