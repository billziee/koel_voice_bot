# KOEL — Deploy (Render) v4

> Supersedes [DEPLOY_V3.md](./DEPLOY_V3.md). Base topology unchanged (still the single-process `koel.combined:app` on Render, self-migrating). v4 adds a scripted deploy path, the env vars that actually activate telephony/dialer/Google-login/org-admin, a real (never-applied) Terraform AWS target, and documents (does not fix) the render.yaml service-naming drift v3 left behind and the frontend/backend branch-tracking split.

## v4 notes / state

- **Terraform AWS target (`infra/terraform/`), written, never applied.** No state file exists anywhere in the repo. It provisions, for an `ap-south-1` deployment: an S3 recordings bucket (KMS-encrypted, 30-day lifecycle), RDS Postgres (Multi-AZ, encrypted, deletion-protected, 7-day PITR), ElastiCache Redis (Multi-AZ, encrypted, AUTH-token, `rediss://`), least-privilege IAM (S3 recordings write + a Bedrock Titan-Embeddings-only `InvokeModel` grant — not `bedrock:*`), and an ECS Fargate service running the *same* image/command as the live Render deployment (`uvicorn koel.combined:app`). VPC/subnets/security groups/ALB target group are inputs to an existing network, not created here. **SageMaker (Whisper/Orpheus) endpoints are deliberately NOT provisioned** — an `aws_sagemaker_model` needs a real trained model artifact (`image_uri` + `model_data_url`), and there isn't one; inventing placeholder values would be Terraform that looks complete but points at nothing, which the file's own header comment calls out as worse than an honest gap. `terraform plan`/review only — no `apply` against a real account.
- **Bidirectional recording is a storage-volume change, not a config one.** `s3_recording_bucket`/`s3_region`/`recording_retention_days` are unchanged from v3, but recordings now capture both the bot's and the customer's audio on both transports (previously only the bot's half, ever) — expect roughly double the per-call storage against the same 30-day retention window.
- **Scripted deploy is additive, not a replacement.** The dashboard/git-push path (branch push → auto-deploy) still works unchanged; `scripts/deploy_render.sh` is for triggering a deploy on demand (e.g. after only an env-var change, or from CI) without touching the dashboard.
- **KOEL_SECRET_KEY** is still the one credential most likely to be skipped when standing up a fresh env group from docs alone — see the boot-warning row above and [`SECURITY.md`](./SECURITY.md) for the full rotation/key list.
