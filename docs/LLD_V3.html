5. Orchestrator (voicebot/pipeline/orchestrator.py) — v3 behavior

Path v2 v3
batch turn _respond_with_filler → _send_bot_turn unchanged when stream_nlp off
streaming turn — _stream_bot_turn: consume respond_stream, speak sentences as they land, filler race + sentiment prosody, lock-serialized; reconcile-or-escalate on a lost final
speculative RAG — O-5: pre-fetch on the smart-turn hold, reuse if the final hasn't diverged, cancel on teardown
cost/budget — O-9: cost.py estimate per turn + polite wrap-up at the ceiling

6. WS handler CallSession (voicebot/ws/handler.py) — v3

Factory-injected BrowserStreamingStt: audio frames route to a long-lived Deepgram session (partials → captions, finals → the same downstream turn), degrading to the unchanged buffered per-utterance path on connect failure. Streaming finals are serialized by a lock (they arrive off the receive loop, so two close finals can't drive overlapping turns). Also wires EscalationHub (3.1) + LiveMonitor (3.3).

9. REST API — v3 additions

  • POST /v1/respond/stream (NLP NDJSON); + model-connections CRUD (BYOK); + Users/org endpoints (6.4); + escalation/monitor endpoints (3.1/3.3). /refresh now consumed by the FE (Q-2).

10. Key algorithms — v3 additions

  • Incremental JSON sentence extraction (nlp/streaming.py) — emits reply sentences as tokens arrive; provably a prefix of the final parse.
  • Speculative RAG reuse (O-5) — fire on hold, reuse iff the final ≈ the speculated partial, else discard.
  • Streaming-final serialization (ws/streaming_stt.py) — asyncio.Lock so callback-driven finals never overlap the turn loop.
  • SET LOCAL hnsw.ef_search (O-10) — transaction-scoped recall/latency knob.
  • BYOK secret handling — encrypt-at-rest + SSRF-guarded egress + resolver.
