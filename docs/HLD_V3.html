KOEL Voice Bot — High-Level Design v3

Supersedes HLD_V2.md (which superseded HLD.md). v3 is the current state after the latency/cost optimization pass (O-1…O-10), the code-quality/engineering pass (Q-1…Q-7), and the first wave of Part-C product features (telephony seams, human-in-the-loop, multi-tenant, BYOK model connections). Every table below carries a v1 / v2 / v3 column so the evolution is legible end-to-end.

What changed since v2 — at a glance

v2 made the AI pipeline fully real and deployed it live. v3 attacks the two things v2 flagged as open: true latency (the streaming + speculation + caching arc) and product/platform depth (multi-tenant, BYOK, telephony, human handoff). It also hardened the code surface: the 3.6k-line App.tsx monolith is decomposed + code-split, TypeScript is on full strict, the rate limiter is Redis-backed for multi-worker correctness, and the test count went 264 → 680.

1. Purpose & scope

Unchanged from v1/v2: a multilingual (EN / HI / Hinglish) outbound voice-bot for Indian financial services — 5 FastAPI microservices (STT, NLP, TTS, CRM, VoiceBot orchestrator) behind a React SPA, run combined as koel.combined:app on the free tier. v3 adds a genuine multi-tenant/BYOK platform layer on top.

3. System context

The five services and the SPA are unchanged in shape. New external dependencies in v3: Deepgram (streaming STT WebSocket), Redis (rate limiter / warm-connection pool at >1 worker), optional FastEmbed/ONNX (local embeddings), and per-tenant BYOK provider endpoints (validated through an SSRF guard before use).

6. Key data flows

6.1 Outbound turn — v3 streaming happy path

Mic frames → (per-bot mode) Deepgram streaming session → interim partial_transcript captions + an utterance final → the same handle_final_transcript the buffered path uses (control-flow, barge-in, cost/budget unchanged) → O-2: NLP streams reply sentences → each fed to sentence-streaming TTS as it lands (O-3 cache short-circuits repeats) → audio streamed back. O-5 speculative RAG may have pre-fetched on the endpointing hold. Falls back to the v2 buffered/batch path on any streaming failure — a turn is never dropped.

6.2 Resilience/degradation (v3)

Every new fast path degrades: streaming STT → buffered transcribe; NLP stream → batch respond(); TTS cache miss → synth; Redis limiter → fail-open (except login, fail-closed); local embedder load failure → hash; BYOK resolve failure → env default.
